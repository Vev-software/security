# Security Policy

If you believe you have found a vulnerability in a VEV repository or service,
do **not** open a public issue.

## Reporting

Report vulnerabilities privately to VEV through an existing private maintainer or
security channel. If you already have a direct contact at VEV, use that route and
ask for the report to be forwarded to the security team.

Include:
- affected repository, version, commit SHA or deployment identifier;
- impact and expected severity;
- reproduction steps or a proof of concept;
- any mitigation you already know.

## Disclosure

VEV coordinates fixes and disclosure case by case. Please avoid public disclosure
until a fix, mitigation or advisory path has been agreed.

## Threat models

Threat models — what a surface holds, its trust boundaries, its controls and its
residual risks — live under [`docs/threat-models/`](./docs/threat-models/).

## Scope

This policy is provisional bootstrap documentation for this repository and should
later be aligned with the canonical org-level process in Vev-software/security.
